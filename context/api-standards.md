Jangan langsung menebak/mengarang endpoint, dan jangan langsung percaya dokumentasi lama tanpa cek ulang.

1. **Cek dulu ke frontend web** (`/Users/asdarsaid/JSI/client`) — cari halaman/komponen yang memakai fitur setara, baca endpoint apa yang dipanggil (`axios.get/post/...`), body/params-nya, dan base URL yang dipakai (cek apakah proyek itu pakai host/proxy khusus seperti `baseUrl2024` — jangan asumsikan semua fitur web pakai host yang sama, lihat § Hasil Rekap untuk contoh nyata 2 host berbeda).
2. **Cocokkan ke repo API** (`/Users/asdarsaid/JSI/api`) — cari controller yang menangani path itu (`grep -rn "@Controller" src/`), baca route (`@Get`/`@Post`/dst.), guard (`@UseGuards`), dan DTO/model yang direspons. Konfirmasi apakah endpoint itu **masih ada, sudah pindah modul, atau sudah dihapus** — jangan asumsikan dokumentasi lama di file ini masih akurat, backend ini terbukti berubah.
3. **Kalau ragu (endpoint tidak ketemu, atau bentuk response tidak jelas dari baca kode saja) — tes langsung** via `curl` read-only ke `https://api.demokrasikreatif.org/{endpoint}` (GET aman langsung; untuk route POST-only, tes dengan body kosong/`{}` untuk lihat apakah balas 422/400 validasi — **route ADA** — vs 404 "Cannot POST/GET" — **route TIDAK ADA**; JANGAN kirim kredensial asli lewat curl). Ini bukti paling kuat, lebih diutamakan daripada baca kode kalau ada konflik.
4. **Laporkan ke user SEBELUM implementasi** — khusus bagian yang: (a) tidak cocok antara observasi web vs repo API vs hasil tes live, atau (b) endpoint/kapabilitasnya sama sekali tidak ditemukan di manapun. Jangan diam-diam mengarang jalan keluar (Aturan #6 CLAUDE.md) — tanya dulu, baru lanjut kalau sudah dikonfirmasi.
5. **Update dokumentasi ini** (`api-standards.md`) begitu ketemu kontrak yang benar — supaya sesi berikutnya tidak mengulang riset yang sama, dan supaya bagian yang ternyata basi jelas ditandai (strikethrough + catatan koreksi, bukan dihapus diam-diam — lihat pola koreksi Auth Flow/Timses di bawah sebagai contoh).

## Mock Mode (aktif sejak 2026-08-21 — lihat progress-tracker.md Decisions)

**Kenapa:** `https://api.demokrasikreatif.org` (base URL production, dikonfirmasi user) diproteksi **Cloudflare Managed Challenge** di seluruh domain (`cf-mitigated: challenge` di response header, HTTP 403 dengan body HTML "Just a moment..." untuk SEMUA request — bukan cuma `/auth/login`, dicoba juga `GET /api`). Ini memblokir client non-browser (axios dari mobile app, `curl`, dst.) di lapisan Cloudflare **sebelum** request sampai ke NestJS. Ini masalah infrastruktur di luar scope repo `jsi-mobile` maupun `api` — butuh perubahan konfigurasi zone Cloudflare (whitelist/bypass Managed Challenge untuk path API) oleh siapa pun yang pegang akses dashboard-nya.

**Cara kerja toggle:**
- `.env`: `EXPO_PUBLIC_USE_MOCK_API=true` → semua service function cek `isMockApiEnabled()` (`src/lib/api/mock.ts`) di awal, dan short-circuit ke data hardcode/canned kalau `true`, skip `apiClient` sama sekali.
- Set `"false"` (atau hapus) begitu Cloudflare sudah dibuka aksesnya — service otomatis balik manggil endpoint asli tanpa perlu diedit lagi (mock ada di cabang terpisah dalam fungsi service yang sama, bukan ganti implementasi).

**Pola yang WAJIB diikuti tiap kali service baru dibuat (dtdoor, gotv, timses, dst.) selama flag ini `true`:**
1. Definisikan data mock secukupnya untuk memverifikasi UI (list kosong/isi, minimal 1 contoh per state yang relevan)
2. Tambahkan cabang `if (isMockApiEnabled()) return mock...(...)` di awal fungsi service, SEBELUM blok `try` yang manggil `apiClient`
3. Simulasikan delay (`mockDelay()`) supaya loading state tetap bisa diverifikasi visual
4. Tiru behavior/pesan error backend asli semirip mungkin (lihat contoh `loginRequestMock` di `src/services/auth.ts`) — supaya tidak ada kejutan pas mock dimatikan
5. Kalau screen butuh visibilitas kredensial/data demo untuk user testing (seperti Login), tampilkan hint singkat yang **hanya render saat `isMockApiEnabled()` true** — jangan biarkan nempel di production build

**Status saat ini:** hanya `src/services/auth.ts` (`loginRequest`) yang sudah punya cabang mock (2 akun demo: `admin.jsi`/`admin123` role admin, `yayat.hidayat`/`timses123` role timses). Modul lain belum ada service-nya sama sekali (Phase 2/3 belum dikerjakan) — begitu dibangun, ikuti pola di atas selama flag masih `true`.

## Struktur Client

```typescript
// src/lib/api/client.ts
import axios from "axios";
import { getToken } from "@/lib/api/token";

export const apiClient = axios.create({
  baseURL: process.env.EXPO_PUBLIC_API_URL,
});

apiClient.interceptors.request.use(async (config) => {
  const token = await getToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

```typescript
// src/lib/api/token.ts — implementasi asli sekarang simpan token + user (lihat Auth Flow poin 6)
import * as SecureStore from "expo-secure-store";

export async function getToken(): Promise<string | null> { ... }

```

Catatan: JWT dari NestJS jauh di bawah batas ukuran `expo-secure-store` (~2048 byte) — diverifikasi saat implementasi Feature 02 (payload login berisi `id`/`nik`/`nama_lengkap`/`roles`, jauh lebih kecil dari batas), tidak perlu pola penyimpanan alternatif.
